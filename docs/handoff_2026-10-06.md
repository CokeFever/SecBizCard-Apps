## OAuth「未驗證」警告 — 真因鏈(重開 session 必讀,別重新誤判)

web editor 授權時一直跳「Google hasn't verified this app / requesting access to
**sensitive** info」。追查順序與**最終真因**:

1. ❌ 一度以為是「scope 不一致」:consent screen 只登記 `drive.file`,但 GIS 隱含帶
   `openid/email/profile`。→ 把這三個非機密 scope 補登記進 Data Access 頁(已完成,
   現為 4 個非機密 scope)。**但警告沒消。**
2. ❌ 一度以為是「等 Google 傳播」。**不是。**
3. ✅ **真因**:授權同意畫面列出 **5 個 scope**,第 5 個是
   **`https://www.googleapis.com/auth/contacts`(讀寫 Google 聯絡人,SENSITIVE)**。
   這個 scope **不是 web editor 來的**(web editor 只用 `drive.file`,非機密),是
   **app(手機端)**的「存到 Google 聯絡人」功能(People API `createContact`)。
   因為整個專案**共用一個 consent screen**,app 的 sensitive scope 污染了整個 brand 的
   驗證狀態 → 任何用這個 consent 的 client(含 web editor)都跳未驗證警告 + 套 100 人上限。

### 關鍵決策(使用者拍板)
- **app 的「存到 Google 聯絡人」功能要保留**(不移除)→ 因此專案**必須走 OAuth
  verification**。drive.file 非機密、免驗;真正要驗的 sensitive scope **只有 `contacts` 一個**。
- `contacts` 是 **sensitive**(非 restricted)→ 標準人工審核,**不需 CASA 第三方安全評估**,
  但要數天~數週。

### BUG 1(HIGH — 擋住 OAuth verification 的 demo 錄製)
`Export Failed: 403 Request had insufficient authentication scopes`(新帳號點「存到
Google 聯絡人」)。根因:`lib/features/contacts/data/contacts_repository.dart` 的存聯絡人
路徑 `signIn()` 後直接用 `account.authHeaders` 呼叫 People API `createContact`,
**從未 `requestScopes([contacts])`**(對比 `drive_repository.dart` L44 有做)。所以:
- 沒授權過 contacts 的帳號 → 403,存不進去(功能對新使用者是壞的)。
- **app 不觸發 contacts 同意畫面 → 錄不出 demo 影片。** 這就是「看不到授權畫面」的根因。
修法:存聯絡人前 `requestScopes([contacts])`,denial 回乾淨 Failure,403 不要原樣丟給使用者。

(handshake/share 流程,gRPC `unavailable` → 友善文案),保留 Retry。
