### 2. App-level OCR tier cache (cache-first + background revalidate)
Replaces the per-screen on-entry `getOcrUsage` call (which caused a visible
flicker on the AI Recognition + scan screens) with one shared provider.
- New: `lib/features/contacts/data/ocr_usage_provider.dart` —
  `ocrUsageNotifierProvider` (`@riverpod` class). Per-uid disk cache via
  `shared_preferences` (key `ocr_usage_cache_<uid>`), seeds `state` instantly,
  revalidates in background. Keyed on `authStateProvider` uid.
- `OcrUsage`/`OcrTier` gained `toMap`/`toBackend` for cache serialization
  (`ocr_tier.dart`). Null-cap semantics (VIP-unlimited vs unknown) preserved.
- Invalidation triggers wired:
  - purchase/restore → `ocrUsageNotifierProvider.notifier.refresh()`
    (`ocr_settings_screen.dart`)
  - RevenueCat `addCustomerInfoUpdateListener` → refresh (`subscriptionSync`
    provider in `subscription_providers.dart`; service pass-throughs in
    `subscription_service.dart`)
  - startup: prefetch provider + register the sync listener on login→home
    (`_warmUpCloudFunctions` in `app_router.dart`)
  - logout: clear per-uid cache before `signOut()` (`app_drawer.dart`)
- Consumers rewired: `ocr_settings_screen` watches the provider (removed its own
  `_loadUsage` + `FirebaseFunctions`); `scan_card_screen` converted to
  `ConsumerStatefulWidget`, badge derives from provider + `hasOwnVisionKeyProvider`.
- `OCRService.preScanStatus()` removed (was the second, drifting `getOcrUsage`
  path); `OcrPreScanStatus` class kept (still used for the badge shape).
- Design guardrail: **cache only affects DISPLAY.** Real quota gating stays on
  the backend on every scan, so a stale cache never grants wrong quota.
- Verified: `fvm flutter analyze lib/` clean AND `fvm flutter build ios --debug

## END-OF-DAY UPDATE — subscription bug found + fixed, build 1.6.0+171 cut

### What happened
User tested the **Android** purchase flow on the current **1.6.0** build. Symptoms:
- Purchase completes ("Thanks for subscribing!" toast) but the AI Recognition
  tier card stays **Basic 5/5** — tier never updates.
- Repeated Subscribe attempts also "succeed"; the 3rd shows Google's
  "You're already subscribed to SecBizCard Plus/Pro".
- "NT$33.00 / 5 min" pricing → **NOT a bug**: Google Play sandbox compresses a
  month into 5 minutes; "Test card, always approves" = no real charge. The order
  confirmation emails to cokeliebhaber@gmail.com are sandbox noise — ignore.

### Root cause (verified against backend code, not guessed)
Backend (`~/_Projects/SecBizCard/functions/src`) is correct and already
deployed (webhook returns 200 = it's live):
- webhook `handleRevenueCatEvent` writes `users/{event.app_user_id}`
  (`subscriptionActive/subscriptionTier`).
- `getOcrUsage` → `resolveTier` reads `users/{request.auth.uid}` (Firebase uid).
- These only line up if RevenueCat's `app_user_id` == Firebase uid.

The app never called `Purchases.logIn(uid)`. `main.dart` sets `appUserID` in
`init()` at startup, but Firebase auth hasn't restored yet → `currentUser` is
null → RevenueCat stays **anonymous** (`$RCAnonymousID:...`). Purchases attach to
the anon id; the webhook writes `users/{anonId}`; `resolveTier` reads
`users/{firebaseUid}` → never sees it → **tier stays Basic forever.**

### Fix (client-side only; backend untouched — no deploy needed)
Commit on `main`: **`fix(subscription): bind RevenueCat app-user-id to Firebase
uid on sign-in`**.
- `SubscriptionService.logIn(uid)` hardened (skips if already mapped) + new
  `logOut()` (reset to anonymous on sign-out).
- New `subscriptionIdentitySync` provider (in `subscription_providers.dart`)
  listens to `authStateProvider`: on sign-in → `logIn(uid)`, on sign-out →
  `logOut()`. Eagerly started at login→home in `app_router.dart`.
- Verified `Purchases.appUserID`/`isAnonymous`/`logIn`/`logOut` exist in
  purchases_flutter 10.13.1; `flutter analyze lib/` clean.
