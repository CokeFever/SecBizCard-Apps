  `lib/l10n/app_*.arb`; generated `lib/generated/l10n/`.

- Kept in English on purpose: `Scan to Exchange`, nav labels, tier names
  (Basic/Plus/Pro/VIP/Flex), `BYOK`, `CV/OCR/AI`, `SecBizCard Plus/Pro`,
  `vCard`/`.vcf`/`.zip`, App Store / Google Play badge text, `EULA`, the vCard
  sample hint, the AI-prompt clipboard text.
- Two intentional literal exceptions: `main.dart` "Initialization Error" (pre-
  localization fatal fallback, no locale context) and the vCard format hint.
- Incidental fixes: `backup_screen` no longer infers error color from message
  text (`_statusIsError` bool, survives translation); `handshake_history`
  status badges use a localized label map instead of raw enum names.
- Verified: `fvm flutter analyze lib/` clean; regex sweep found no other
  hardcoded UI strings.

### 2. App-level OCR tier cache (cache-first + background revalidate)
Replaces the per-screen on-entry `getOcrUsage` call (which caused a visible
flicker on the AI Recognition + scan screens) with one shared provider.
- New: `lib/features/contacts/data/ocr_usage_provider.dart` —
  `ocrUsageNotifierProvider` (`@riverpod` class). Per-uid disk cache via
  `shared_preferences` (key `ocr_usage_cache_<uid>`), seeds `state` instantly,
  revalidates in background. Keyed on `authStateProvider` uid.
- `OcrUsage`/`OcrTier` gained `toMap`/`toBackend` for cache serialization
  (`ocr_tier.dart`). Null-cap semantics (VIP-unlimited vs unknown) preserved.
- Invalidation triggers wired:
  - purchase/restore → `ocrUsageNotifierProvider.notifier.refresh()`
    (`ocr_settings_screen.dart`)
  - RevenueCat `addCustomerInfoUpdateListener` → refresh (`subscriptionSync`
    provider in `subscription_providers.dart`; service pass-throughs in
    `subscription_service.dart`)
  - startup: prefetch provider + register the sync listener on login→home
    (`_warmUpCloudFunctions` in `app_router.dart`)
  - logout: clear per-uid cache before `signOut()` (`app_drawer.dart`)
- Consumers rewired: `ocr_settings_screen` watches the provider (removed its own
  `_loadUsage` + `FirebaseFunctions`); `scan_card_screen` converted to
  `ConsumerStatefulWidget`, badge derives from provider + `hasOwnVisionKeyProvider`.
- `OCRService.preScanStatus()` removed (was the second, drifting `getOcrUsage`
  path); `OcrPreScanStatus` class kept (still used for the badge shape).
- Design guardrail: **cache only affects DISPLAY.** Real quota gating stays on
  the backend on every scan, so a stale cache never grants wrong quota.
- Verified: `fvm flutter analyze lib/` clean AND `fvm flutter build ios --debug
  --no-codesign` succeeds (codegen + pod install + Xcode build all pass).

## iOS sandbox purchase testing (clarified today)

- Do NOT change the phone's main Apple ID, and do NOT add the sandbox account to
  the App Store. Sandbox is separate from the device Apple ID.
- app login (Google `cokeliebhaber@gmail.com`, a NON-VIP account so finite tiers
  show) is unrelated to the Apple payment sheet.
- On TestFlight, purchases automatically run in **Sandbox** (no real charge).
  Flow: login app with Google → tap subscribe → Apple sheet shows
  `[Environment: Sandbox]` → enter the **sandbox tester** Apple credentials
  (created in App Store Connect → Users and Access → Sandbox → Testers).
- **OPEN QUESTION for the user:** confirm the sandbox tester's email is a clean
  address NOT already used as a real Apple ID (recommend a `+sandbox` alias like
  `cokeliebhaber+sandbox@gmail.com`). If the sandbox tester reused a real Apple
  ID email, the payment sheet step will fail.
