## 🔴 P0 事件:1.6.3 backup/restore 全壞 — 根因與修復(重開 session 必讀)

### 症狀
1.6.3+186 裝到測試機後:按 Back Up Now → `PlatformException(exception, ERROR, null, null)`;
Restore → "No backup found"(但 Drive 的 `SecBizCard/ixo_app_backup.zip` 肉眼看得到、web
editor 也讀得開)。1.6.1/1.6.2 一路正常。

### 繞過的錯誤理論(記下來,避免重走)
這案極其容易誤判,以下理論**都被證據推翻**:
- ❌ consent screen 加 contacts scope 讓既有 drive.file grant 失效 → 搜尋證實:加 scope 不影響既有 grant。
- ❌ drive.file 身分不匹配(重裝/grant 輪替看不到舊檔)→ 第一份調查的結論,但不符「1.6.2 正常、原地升級 1.6.3 才壞」。
- ❌ release 簽章 SHA-1 沒註冊 → 簽章 `5e4dac...` 其實有註冊;且 1.6.1/1.6.2 同簽章正常。
- ❌ 網路問題 → 第一次測試機沒連到 Google(企業 BYOD 網擋 googleapis)造成假的 NETWORK_ERROR,換網路後排除。

### ✅ 真正根因(實機 logcat 定因)
- app **只有一個共用的 `GoogleSignIn` 實例**(`auth_repository.dart` 的 `googleSignInProvider`,
  `serverClientId=769422548283-rvuciu2...`),同時注入 DriveRepository(drive.file)和
  ContactsRepository(contacts)。
- **1.6.3 的 contacts 修復(commit `5c69485`)新增了** `_googleSignIn.requestScopes([contactsScope])`
  —— 這段 1.6.1/1.6.2 **沒有**。
- 一旦這個共用 grant 請求過 **contacts(待驗證的 sensitive scope)**,之後 drive 用**同一個 grant**
  要 token 時,Google 後端判 **`BAD_REQUEST`**(GMS Auth: `GetToken failed with status code:
  BAD_REQUEST`)→ backup/restore 的 drive token 拿不到 → 全壞。
- 1.6.1/1.6.2 沒有 contacts requestScopes,grant 永遠只有 drive.file → 不受影響。
- 重新登入會拿到乾淨 grant → 暫時正常,直到再次觸發 contacts 又污染。

**一句話:drive.file(非機密)和 contacts(待驗證 sensitive)共用一個 GoogleSignIn grant,
contacts 污染了 grant,連帶讓 drive token 被 Google 拒發。**

### ✅ 修復(commit `32118db`,已出 1.6.3+187 驗證通過)
把單一共用 GoogleSignIn **拆成兩個獨立實例**(`auth_repository.dart`):
- `driveGoogleSignIn`(scopes: drive.file)→ 只給 DriveRepository + AuthRepository
- `contactsGoogleSignIn`(scopes: contacts)→ 只給 ContactsRepository
- signOut/deleteAccount 兩個都登出;privacy wipe 不變。
→ drive 的 grant 永遠乾淨、不再被 contacts 污染。**1.6.3+187 真機(Pixel 9 Pro,release
簽章)驗證:登入 OK、restore 找得到檔、backup 成功。**

**✅ 收官驗證(2026-10-07,P0 結案):** 在 187 真機上,先執行「存到 Google 聯絡人」(觸發
contacts 獨立實例請求 contacts scope)→ 再按 Backup Now → **backup 仍正常**。這證明兩個 grant
徹底隔離:contacts 的 scope 請求不再污染 drive 的 token。整個 P0(根因/修法/驗證)閉環,結案。
(註:cokefever 帳號 contacts 不跳未驗證警告,是因為該帳號先前已授權過 contacts;全新帳號在
verification 核准前仍會看到未驗證警告,Advanced 繞過 —— 但那不影響 backup,因為已分離。)

### ⚠️ 教訓(務必遵守)
- **不要在同一個 GoogleSignIn 實例上混用不同 scope domain。** 未驗證/sensitive scope 會污染
  同 grant 的其他(即使非機密的)scope 的 token 取得。不同用途 = 不同 GoogleSignIn 實例。
- **debug build 無法驗證 Google 登入**:本機 debug keystore SHA-1(如 `0a5c78...`)未註冊 →
  `ApiException: 10 (DEVELOPER_ERROR)`,連登入都過不了。驗證授權相關功能**一定要用 release 簽章
  build**(走 Cloud Build → Play internal)。
- 診斷授權問題**直接接實機 adb logcat**,不要純讀 code 推理(本案純推理繞了 5+ 次錯路)。

### 資料安全(全程確認)
使用者 10/5 雲端備份**從未受威脅**:auth 在任何寫入前就 throw、empty-guard(空資料連 force 都擋)、
delete-only-if-safe、restore 不寫雲端。唯一真實風險是**登出會清本機資料** —— 事件中特別警告使用者
別登出(restore 當時壞的,登出會刪本機又救不回)。
