## TL;DR — what happened today

Tested subscriptions on Android (build 1.6.0+171) and found the purchase flow
broken in several ways. Root-caused each, fixed across app + backend, and cut
two new builds. **All fixes are shipped and building; backend reconciliation is
deployed live.** Next step is a clean-sandbox re-test on 1.6.0+173.

Three defects found + fixed today:

1. **Purchase succeeded but tier stayed Basic** (from yesterday's 171 test).
   Cause: app never called `Purchases.logIn(uid)`, so RevenueCat stayed
   anonymous, the webhook wrote `users/{anonId}` and `resolveTier` read
   `users/{firebaseUid}`. Fixed on 1.6.0+171 already (`subscriptionIdentitySync`).

2. **Plus→Pro left BOTH active; ~20 order emails; tier updated slowly; cancel
   lagged.** Causes + fixes shipped in **1.6.0+172**:
   - App: `purchase()` now passes `StoreProductChangeInfo(withTimeProration)`
     with the current active product id → Play REPLACES instead of stacking.
   - App: optimistic tier update from RevenueCat's returned tier
     (`setTierOptimistic`) + `refresh()` reconciles used/cap.
   - App: paywall hides the already-owned tier.
   - App: OCR tier refreshes on app resume (foreground).
   - Backend (DEPLOYED): `shouldPersistDecision` reconciliation — a lower-tier
     event can't clobber an active higher tier; an expire/cancel only clears the
     tier it actually refers to. (commit `01c5f6c`, deploy run 35889994274.)
   - The ~20 emails are Google Play **sandbox** order receipts (5-min renewals ×
     stacked subs), NOT app/backend generated. Confirmed no email code exists.
   - "NT$33/5 min" pricing is sandbox time-compression, not a bug.

3. **No cancel path for Pro; no restore for Pro; downgrade shouldn't exist.**
   Product rule confirmed with user: **no in-app downgrade** — plans only go up
   (Basic→Plus→Pro) or are cancelled (→ expire → Basic). Fixes in **1.6.0+173**:
   - Tier card now shows, for paid (Plus/Pro) users, **Manage subscription**
     (opens the store's manage page via RevenueCat `managementURL` — the cancel
     path) + **Restore purchases** (Apple 3.1.1; the only restore entry a Pro
     user can reach, since Pro never opens the paywall sheet).
   - Basic: Subscribe only. Plus: Upgrade to Pro + Manage + Restore. Pro: **no
     upgrade/downgrade button**, only Manage + Restore.
   - Backend comment updated to state the no-downgrade rule (logic unchanged →
     NOT redeployed). commit `98b2a8b`.
