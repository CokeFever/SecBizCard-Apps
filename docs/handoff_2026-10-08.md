### ⚠️⚠️ CSP 血淚史(重開 session 必讀,勿重走)
**第一版嚴格 CSP(f228988)直接打爛線上頁面 —— editor 全空白。**
- 根因:Nuxt 4.3.0 SSG 會注入一段**可執行的 inline** `<script>window.__NUXT__.config={...}</script>`
  (runtime config);`script-src` 沒有 `'unsafe-inline'` → 瀏覽器拒執行 → hydration 失敗 → 空白。
  (另有 `type="application/json"` 的 `unhead:payload` / `__NUXT_DATA__`,那兩個非可執行、CSP 不擋。)
- **教訓 1:CSP 不能只做靜態 review 就上線。** 第一版通過了靜態 review 仍打爛 prod,因為沒做
  執行期 hydration 實測。**任何改 CSP 的 PR 必須在嚴格 CSP 下用真/headless 瀏覽器載頁驗證 hydration。**
- **教訓 2:`**` CSP 規則同時蓋 `/flutter/index.html`**(app handshake/deep-link 頁),該頁自己也有
  2 支 inline script。全站一條 CSP 就要連 Flutter 頁的 inline script 一起處理。
- 暫時處置(a90dc2c):`script-src` 加回 `'unsafe-inline' 'wasm-unsafe-eval'` 讓頁面復活
  —— 但這等於廢掉大半 script XSS 防護,是 stopgap 不是終解。
- **最終解(ec615c4,方案 2 「消除 inline script」):** 用 Nuxt `prerender:generate` build hook
  把 runtime-config bootstrap 外部化到 `/_nuxt_config/<hash>.js`;handshake 頁兩支 inline 也移到
  `/flutter/handshake.js`。generated HTML 全站**零可執行 inline script**,CSP 得以回到嚴格
  `script-src 'self' <google>`(拿掉 unsafe-inline + wasm-unsafe-eval)。**不用 hash CSP、不改
  deploy pipeline**(hash 綁 buildId 太脆,棄用)。workflow 已 headless Chrome 實測 /editor + /
  在嚴格 CSP 下 hydration 無違規。
- **驗證(已 curl 確認上線):** `script-src` 無 unsafe-inline;/editor 與 /flutter inline script 數
  = 0;`/_nuxt_config/<hash>.js` 與 `/flutter/handshake.js` 皆 200 + `text/javascript`。

### ⚠️ L2 部署曾失敗一次(commit `3bb69fc`)→ 已修(`212d6bb`)
`3bb69fc` 的 hosting 部署 **CI 失敗**(我當初用 `tail -4` 看 log 誤判成成功 —— 教訓:務必用
`gh run view <id> --json conclusion` 明確讀結論,不要靠 tail 猜)。期間線上仍是前一版 `18affab`
(正常),使用者零影響。
- 根因:`npm audit fix` 用**新版 npm** 寫出的 lockfile,CI 的 **npm 10.8.2(Node 20)** 判定
  out-of-sync(`npm ci` 報 `Missing: unplugin@3.4.0 from lock file`)。本機 Node 26 的 `npm ci`
  不會重現 → 必須用 `npx npm@10.8.2 ci` 才能在本機重現 CI 的檢查。
- 修法(`212d6bb`):`npx npm@10.8.2 install` 重產同步 lockfile(只動 package-lock.json),
  用 `npx npm@10.8.2 ci` 本機驗證通過,build/generate/404 測試全綠,audit 數不變(25,dev-only)。
  重新部署 **CI conclusion=success(明確查證)**,線上驗證通過。
- **教訓:改 lockfile 的 CI 用 `npm ci`(嚴格),本機驗證必須用相同 npm 版本(`npx npm@<CI版本>`),
  否則本機 `npm install`/新版 npm 的寬鬆行為會漏掉 CI 才會爆的同步問題。**
